# Insight

**A lightweight, industrial-grade C++ Array computing framework for signal processing and GPU acceleration.**

Insight is a language-neutral Array library inspired by **PaddlePaddle** (operator registration, backend HAL, public device behavior), **Torch7** (clean C API, TH/THC spirit), and **NumPy/CuPy** (array semantics, strided views, interoperability, and GPU execution). It keeps the user device model simple (`cpu:0` / `gpu:0`) while allowing the active GPU backend to be CUDA, ROCm, IXUCA, SDAA, or another vendor implementation selected at initialization.

## Design Direction

Insight should feel like a language-independent NumPy/CuPy core rather than a Python-first wrapper. The main design contracts are:

- **Array, not Tensor** -- the core object is `ins::Array`, focused on numerical arrays, signal processing, and backend execution without autograd.
- **Simple public devices** -- users choose `cpu:0` or `gpu:0`; backend names such as `cuda`, `rocm`, `ixuca`, or `sdaa` are diagnostics and explicit selection knobs, not public place strings.
- **One active GPU backend** -- one process selects one GPU implementation behind `gpu:*`, configured by `INSIGHT_GPU_BACKEND` or init options.
- **Explicit protocols** -- Array storage/layout, dtype promotion, OpSchema, ArrayIterator, structured fallback, and interop are modeled explicitly instead of guessed from raw pointers.
- **Lua code generation** -- repetitive operator schema/dispatch metadata is generated by Lua using backend-neutral `host` / `device` adapters that CUDA/ROCm/SDAA can consume.
- **Cross-language parity** -- C++, Python, Lua, and Julia bindings share the same C++/C ABI core, with language-specific indexing and shape conventions handled at binding boundaries.

See [`docs/architecture.md`](docs/architecture.md) for the full architecture contract and [`docs/windows-cuda.md`](docs/windows-cuda.md) for Windows CUDA continuation work.

## Features

- **Unified API** -- `ins::Array` works on the current `CPUPlace()` or `GPUPlace(0)` with public device strings `cpu:0` and `gpu:0`.
- **Backend Selection** -- CUDA, ROCm, IXUCA, SDAA, and future GPU plugins sit behind the unified GPU place; use `INSIGHT_GPU_BACKEND=cuda|rocm|ixuca|sdaa` to force one.
- **Zero-Copy Views** -- `reshape`, `transpose`, slicing, and partial indexing use shared storage, strides, and offsets.
- **Structured Dispatch** -- OpSchema and schema-aware kernel launch keep scalar attrs, arrays, fallback, and writeback explicit.
- **ArrayIterator** -- broadcast, contiguous fast paths, non-contiguous strides, offsets, and reductions are represented once for reusable kernels.
- **Device HAL** -- ABI-stable plugin system for allocation, copy, streams, events, profiling, diagnostics, and kernel registration.
- **Signal Processing** -- 89 functions across 14 submodules (windows, waveforms, B-splines, filter design, convolution, filtering, spectral analysis, wavelets, acoustics, radar, demod, peak finding, estimation, I/O).
- **Half-Precision** -- fp16/bf16 support via `half_utils.h`/`half_utils.cuh`, with CPU/GPU coverage where supported.
- **Language Bindings** -- Python (pybind11), Lua (sol2), Julia (ccall) with per-module wrappers and signal sub-namespaces.
- **Interop** -- Python NumPy protocol and DLPack-style entry points are part of the core direction, with explicit host/device copy semantics.
- **No Autograd** -- Insight stays lightweight and focused on array computing.

## Architecture

```
insight/
├── include/insight/
│   ├── core/           # Array, Shape, Strides, DType, Place, OpSchema, ArrayIterator
│   ├── ops/            # Frontend API (elementwise, fft, signal, linalg, etc.)
│   ├── io/             # I/O (csv, print, sndfile)
│   ├── c_api/          # C ABI interfaces (array, kernel, dtype, place, profiler)
│   └── generated/      # Lua-generated operator manifests and schema metadata
├── src/
│   ├── core/           # Array implementation, memory, schema launch, device init
│   ├── ops/            # Frontend operator logic
│   └── internal/       # Internal utilities
├── backends/
│   ├── cpu/            # CPU runtime + kernels (OpenMP + FFTW + OpenBLAS)
│   ├── cuda/           # CUDA backend (cuBLAS + cuFFT + Thrust)
│   ├── rocm/           # ROCm/HIP backend when available
│   ├── ixuca/          # IXUCA backend
│   └── sdaa/           # Tecorigin SDAA runtime backend
├── bindings/
│   ├── python/insight/ # pybind11 bindings (per-module wrappers)
│   ├── lua/insight/    # sol2 bindings (dual calling convention)
│   └── julia/          # ccall bindings (Insight.jl)
├── tools/codegen/      # Lua 5.1-compatible backend-neutral generator
├── tests/
│   ├── cpu/            # CPU tests
│   ├── cuda/           # GPU tests reused by CUDA/SDAA-compatible validation
│   └── python_align/   # NumPy precision alignment tests
└── demos/              # Example programs (C++, Python, Lua, Julia)
```

## Quick Start

### Build from Source

**Linux / macOS:**

```bash
git clone https://github.com/PlumBlossomMaid/Insight7.git
cd Insight7
mkdir build && cd build
cmake .. \
    -DCMAKE_BUILD_TYPE=Release \
    -DINSIGHT_WITH_CUDA=ON \
    -DINSIGHT_WITH_ROCM=OFF \
    -DINSIGHT_WITH_SDAA=OFF \
    -DINSIGHT_USE_FFTW3=ON \
    -DINSIGHT_USE_OPENBLAS=ON
cmake --build . -j$(nproc)
```

Select a GPU backend at runtime:

```bash
export INSIGHT_GPU_BACKEND=cuda   # or rocm, ixuca, sdaa
```

**Windows CUDA (MSVC + Ninja):**

```powershell
# Prerequisites: Visual Studio 2022+ C++ workload, CMake, Ninja, CUDA Toolkit 11.7+
call "C:\Program Files\Microsoft Visual Studio\2022\Community\VC\Auxiliary\Build\vcvarsall.bat" x64
$env:CUDA_PATH = "C:\Program Files\NVIDIA GPU Computing Toolkit\CUDA\v12.3"
$env:PATH = "$env:CUDA_PATH\bin;$env:PATH"

cmake -S . -B build-cuda-win -G Ninja ^
    -DCMAKE_C_COMPILER=cl.exe ^
    -DCMAKE_CXX_COMPILER=cl.exe ^
    -DCMAKE_BUILD_TYPE=Release ^
    -DINSIGHT_WITH_CUDA=ON ^
    -DINSIGHT_WITH_ROCM=OFF ^
    -DINSIGHT_WITH_SDAA=OFF ^
    -DINSIGHT_BUILD_TESTS=ON ^
    -DCMAKE_CUDA_ARCHITECTURES="75;80;86;89" ^
    -DCMAKE_PREFIX_PATH="C:/vcpkg/installed/x64-windows"
cmake --build build-cuda-win -j %NUMBER_OF_PROCESSORS%

$env:INSIGHT_GPU_BACKEND = "cuda"
$env:PATH = "$PWD\build-cuda-win\backends\cpu;$PWD\build-cuda-win\backends\cuda;$env:CUDA_PATH\bin;$env:PATH"
ctest --test-dir build-cuda-win -R "GPU|CUDA" --output-on-failure -j 8
```

More Windows CUDA details are in [`docs/windows-cuda.md`](docs/windows-cuda.md).

> **Note:** For plot functionality, install [gnuplot](http://www.gnuplot.info/) and ensure it is in your `PATH`.

### Lua Codegen

```bash
cmake --build build --target insight_codegen
lua tools/codegen/gen.lua build/generated/codegen
```

The generator is intentionally compatible with Lua 5.1, 5.2, 5.3, 5.4, and LuaJIT. It emits deterministic manifests under `include/insight/generated/` and `docs/` and uses backend-neutral `host` / `device` adapters rather than platform-specific schema keys.

### Install Language Bindings

**Python** (requires CMake build first):
```bash
pip install .
```

**Lua** (via luarocks, requires CMake build first):
```bash
luarocks make bindings/lua/insight-1.0-1.rockspec --local
```

**Julia**:
```julia
push!(LOAD_PATH, "/path/to/Insight7/bindings/julia")
using Insight
```

## Examples

### C++

```cpp
#include "insight/insight.h"
using namespace ins;

int main() {
    init();
    set_device(GPUPlace(0));  // public place: gpu:0, active backend selected by init/env

    Array a = ones({1000, 1000}, DType::F32);
    Array b = randn({1000, 1000}, DType::F32);
    Array c = matmul(a, b);

    Array row = c.at({0});
    Array w = signal::hann(256);
}
```

### Python

```python
import insight as ins

print(ins.get_device())               # "gpu:0" or "cpu:0"
print(ins.active_gpu_backend_name())  # "cuda", "sdaa", ... when GPU is active

a = ins.rand([1000, 1000])
b = ins.randn([1000, 1000])
c = a @ b

row = a[1]
sub = a[1:, ::2]
w = ins.signal.hann(256)
```

### Lua

```lua
local ins = require("insight")

print(ins.get_device())       -- "gpu:0" or "cpu:0"
print(ins.gpu_version())      -- active GPU runtime version, 0 if no GPU

local a = ins.rand({1000, 1000})
local b = ins.randn({1000, 1000})
local c = ins.matmul(a, b)
local row = a[1]
local w = ins.signal.hann{n=256}
```

### Julia

```julia
using Insight

dt, id = Insight.get_device()  # public kind id + device id; GPU means gpu:0

a = Insight.rand(Int64[1000, 1000], Insight.float32)
b = Insight.randn(Int64[1000, 1000], Insight.float32)
c = Insight.matmul(a, b)
row = a[1]
```
